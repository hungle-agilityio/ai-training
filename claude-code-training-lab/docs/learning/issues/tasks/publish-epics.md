# [TASK] publish the epics as issues

- **Requester:** Hung Le, project owner
- **Reported on:** 2026-10-19
- **Type:** Task
- **Labels:** `task`, `tooling`

## Summary

Put the three epics of the Claude Code practices work on GitHub as issues, so that every piece of work has a number, a place and an owner. Today the repository has almost no issues, and the plan lives only in documents on the owner's computer. The work touches the project's issue list on GitHub and the documents that list the work. Nothing visible to users of the ReviewRadar app changes.

The work is done through the official GitHub connection of the assistant, which also checks that the assistant can create issues and attach one issue to another.

## Scope

- **Included:** one issue for each of the three epics; one closed issue that gathers all the work already done; one issue for each piece of work that is not finished yet; attaching each of these to its epic; ticking the finished pieces in the epics; writing the new issue numbers in the lists of work.
- **Not included:** doing the unfinished work itself; the optional ideas that have no real use yet; moving old issues from the previous tracker; any change to the reviews app.

## Done when

Each item must be something a person can check without technical help.
- [ ] The issue list of the repository shows three epic issues, each with its pieces of work listed under it.
- [ ] One closed issue lists the work already done, and each epic points to it for its finished pieces.
- [ ] Each piece of work that is not finished has its own open issue, attached to its epic.
- [ ] Every row in the lists of work shows an issue number.
- [ ] The assistant created at least one issue and attached one issue to another through its GitHub connection.

## Steps to check the result

1. Open the issue list of the repository `hungle-agilityio/ai-training` on GitHub.
2. Find the three issues whose titles start with `[EPIC]`. Open each one and check that its pieces of work are listed.
3. Open the closed issue about work already in place and check that it names the finished pieces.
4. Open the epic about moving the project to GitHub and check that the issue about protecting the repository is attached to it.
5. Open the lists of work in the project documents and check that no row is left without an issue number.

## Expected result

Three open epics, one closed issue for finished work, and one open issue for each unfinished piece, all attached to the right epic. No piece of work is missing from the issue list.
