# Decisions during build: T4 (#541)

| Question | Chosen | Rejected | Why | From |
|---|---|---|---|---|
| Who builds the task? | Built by hand at the owner's request of 2026-11-12, pull request into the epic branch | Waiting for the loop | The owner wants the epic cleared sooner | owner |
| Which fetcher does the probe use? | Its own `fetch(url, timeout) -> Reply(status, body, problem)` | `fetch` of `ops/live_check.py` | That one returns no body and does not tell a timeout from a failed connection, and AC1 and AC2 need both | build |
| How is `down_since` stored? | The ISO time with its zone offset, as the clock gives it (UTC in a real run) | A local time without offset | The minutes of the "back" message must not depend on the machine's zone | build |
| A 200 answer whose body is `ok` plus white space | A failure, `HTTP 200` | Up | AC1 says the body is `ok`; `/healthz/` sends exactly that | build |
| The "back" message after one minute | `... is back after 1 minutes` | A singular form | AC2 fixes the text `after <m> minutes` | build |
| An error inside the probe itself (a broken flow config, a state folder that cannot be written) | One line `uptime: <error type>` on stderr, exit 0 | A traceback and a non-zero exit | AC1: the script always exits 0, so the loop line goes on | build |
