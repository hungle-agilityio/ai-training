# Decisions during build: T3 (#540)

| Question | Chosen | Rejected | Why | From |
|---|---|---|---|---|
| When are the pull requests of the plan read, before or after Render's deploy list? | Before the deploy list, with the other git work | After the deploy list, just before printing | AC2: a failing git command stops before any Render call; the printed order of AC5 is unchanged | build |
| How are tags and their commits read? | One `git tag --list v* --format=...` with the peeled commit of annotated tags | `git for-each-ref` or one `rev-parse` per tag | AC6 allows only tag listing, `rev-parse`, `merge-base`, diff and `log`; one call reads every tag | build |
| Which folder settings does `merged_pull_requests` use? | `release.configure(config)` with the flow config the rollback loaded | The values `release.py` set at import | The client-facing split follows the same config as the rest of the run (`config_path`) | build |
| A Render answer that is 2xx but not JSON | Exit 1 with `Render API failed: unreadable answer` | A crash with a traceback | The issue does not name it; one line on stderr like every other failure | build |
| How is `createdAt` compared? | Parsed as an ISO date, a date without an offset read as UTC; an item without a readable date is skipped | String comparison | A date compares correctly whatever its precision, and mixed dates never crash | build |
| Does `request` follow a redirect? | No: a 3xx is an answer other than 2xx (`Render API failed: HTTP <status>`) | urllib's default opener | A followed redirect would send the Bearer key to another host and turn the POST into a GET (code review) | build |
| When is `ops/release.py` imported? | Inside the run, after the rollback's own config is loaded | At module load | `release.py` loads the default config on import; a broken config is then the rollback's one-line refusal, not a traceback (code review) | build |
| A `git` that cannot start (no PATH, missing folder) | `git <arguments> failed: <reason>`, exit 1 | A traceback | AC2: a failing git command is one line on stderr | build |
