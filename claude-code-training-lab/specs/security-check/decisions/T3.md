# Decisions during build: T3 (#507)

| Question | Chosen | Rejected | Why | From |
|---|---|---|---|---|
| Where is the AC7 block built? | In `make_plan`, into `Plan.security`; `describe` prints it | Printing it in `main` | The block sits right after the Tag line; a Plan built without it prints no block | build |
| Where does the app folder come from? | `security_check` reads `flow_config.load()` itself, before the temp dir is made | Passing it from `release` | Keeps the `run_security(sha, since, cwd)` signature the tests use | build |
| Which errors leave `run_checks`? | Only a failed worktree add or a temp-dir OSError; everything else becomes "could not run" | Catching every error | A release with no checkout cannot be judged, so `main` refuses it | build |
| Which helper do the new release tests use? | Their own helper | The `run` helper of `test_release.py` | That helper now stubs `run_security` | build |
| What does the new `except` in `main` cover? | `TimeoutExpired` and `OSError` of any git or gh call | Only the worktree add | One clear message instead of a traceback | build |
| How is the diff read? | By hunk counts | Treating every `+++` line as a header | An added line that starts with `++` is still scanned | build |
| Odd paths? | One trailing tab removed; git-quoted paths unquoted | Ignoring them | Names with spaces or special characters still get a correct path | build |
| Tracked symlinks on a first release? | Skipped | Reading them | They could point outside the worktree | build |
| pip-audit exit 1 with a dependencies list and no vulns? | Not ok, with no lines | Treating it as ok | Literal AC3: exit 1 is a failure | build |
| `check --deploy` fails with no security line and empty stderr? | Not ok, no lines | Inventing a message | Nothing true to report beyond FAILED | build |
| A carriage return or Unicode line separator inside an added line | The diff is split on newlines only, and the tail after a carriage return is scanned under the same line number | Reading the diff as bytes | The issue fixes text mode for every command; the tail must still be scanned | build |
| A tail that starts with `-` or `+`? | Scanned as well: after an added line every line up to the next header is scanned, also past the hunk's count | Trusting the hunk count | Scanning one line too many is safe; skipping one is not | build |
| Line numbers on a first release? | Counted on newlines only, as in the diff | `str.splitlines()` | A form feed or Unicode separator must not shift the reported line | build |
| Known gaps? | Files git treats as binary and non-UTF-8 files are not scanned; a file line built to look like a diff header after a carriage return (`diff --git`, `@@`) can hide what follows it | Scanning bytes; adding `--text` to the diff | The issue fixes the diff command and text mode; raised in the pull request | build |
| A failed worktree remove? | Ignored; no `git worktree prune` | Failing the release | The scratch folder is still deleted; the checks already ran | build |
