# Decisions during build: T5 (#497)

| Question | Chosen | Rejected | Why | From |
|---|---|---|---|---|
| Does "inside a folder" match the whole folder name? | Yes, prefix `<app_dir>/<code_dir>/` (with app_dir `.`, `<code_dir>/`) | A bare name prefix | It would also match `reviews_old/` | build |
| Why does the prefix include the app folder? | `git diff --name-only` prints paths from the repository root whatever the working folder | Prefix with the code folder only | Paths would never match when the app folder is below the root | build |
| Does a pull request that only deletes a file in a code folder count as client-facing? | Yes, the diff output is taken as it is (same choice as T1) | Leaving deleted files out | Same choice as T1 | build |
| A merge commit with no `#n` in its subject? | Skipped before any diff, as on main | Listing it as internal | It is not a pull request | build |
| An empty `code_dirs`? | Every pull request is internal | An error | No code folder means nothing can be client-facing | build |
| A failing `git diff`? | Reported by the existing "git or gh failed" line, exit 1 | A new error path | The existing handling already covers it | build |
| One `git diff` per merged pull request, or batching? | One per pull request | Batching | A release holds one sprint's merges | build |
| What happens to `Plan.pull_requests`? | Replaced by two fields, `client_facing` and `internal` | Keeping it | Nothing else in the repository reads it | build |
| The release notes page and `.claude/project-instructions.md`? | Out of scope of this issue | Changing them here | No AC asks for it | build |
