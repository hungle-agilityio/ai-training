# Spec: auto-deploy

## Summary

ReviewRadar runs on Render's free plan at a `*.onrender.com` address. Render builds and starts it again after each push to `main`, but only once the GitHub `Checks` workflow is green. Each start creates a fresh SQLite database and fills it with the demo data. The site is public and asks search engines not to index it. Pages look the same as today; the only visible changes are the address and a wait of about a minute when the site has been asleep.

## Acceptance criteria

Settings and dependencies:

- **AC1.** `gunicorn` and `whitenoise` are runtime dependencies in `pyproject.toml`, locked in `uv.lock`; `uv sync --frozen` and the `Checks` workflow still pass.
- **AC2.** `reviewradar/wsgi.py` exists and exposes `application`, so `gunicorn reviewradar.wsgi` starts the app.
- **AC3.** `ALLOWED_HOSTS` keeps `localhost`, `127.0.0.1` and `[::1]` (issue #61) and adds every host listed in the environment variable `DJANGO_ALLOWED_HOSTS` (comma separated, spaces ignored). When the variable is not set, `ALLOWED_HOSTS` is exactly the three local hosts.
- **AC4.** With `DJANGO_DEBUG=0`, the app refuses to start (`ImproperlyConfigured`) when `DJANGO_SECRET_KEY` is missing or equals `dev-only-insecure-key`. With debug on, the dev key still works as today.
- **AC5.** Static files are served by WhiteNoise: its middleware sits right after `SecurityMiddleware`, `STATIC_ROOT` is `staticfiles/` in the project folder (git-ignored), and after `collectstatic` the page `/dashboard/` loads `app.css` with HTTP 200 when debug is off. The test suite still passes without running `collectstatic` first.
- **AC6.** Behind Render's proxy, Django treats requests as HTTPS: `SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")`. `CSRF_TRUSTED_ORIGINS` is `https://<host>` for each host from `DJANGO_ALLOWED_HOSTS`.
- **AC7.** Every HTML page (the ones that extend `reviews/base.html`) has `<meta name="robots" content="noindex, nofollow">` in its head.

Render setup:

- **AC8.** A `render.yaml` Blueprint at the repository root defines one free Python web service named `reviewradar`, region `singapore`, `rootDir: claude-code-training-lab`, branch `main`, Python 3.11, `autoDeployTrigger: checksPass`, and health check path `/dashboard/`.
- **AC9.** Its build command installs the locked runtime dependencies only (no dev group, so no Playwright) and runs `collectstatic`. Its start command runs, in this order: `migrate`, `seed_demo_data`, then `gunicorn reviewradar.wsgi` bound to `0.0.0.0:$PORT`.
- **AC10.** Its environment: `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS` set to the service host (`reviewradar.onrender.com`, or the name Render gives if that one is taken), `DJANGO_SECRET_KEY` generated by Render (`generateValue: true`), `PYTHON_VERSION` 3.11. No secret value is written in the repository.
- **AC11.** `claude-code-training-lab/README.md` has a "Deploy" section: the live address, that it sleeps after 15 idle minutes and wakes in about a minute, that data resets to the demo data on each start, that a deploy starts only after `Checks` is green on `main`, and the one-time steps only the owner can do (below).

Live result, checked by the owner after the one-time setup:

- **AC12.** Opening the live address shows the Dashboard with the demo branches (Airport, Downtown, Riverside) and their scores, with styles loaded, over HTTPS. `/reviews/`, the CSV export and the JSON export work.
- **AC13.** After a pull request is merged into `main`, Render deploys that commit by itself once `Checks` is green (its deploy list shows the commit). A push to `main` whose `Checks` fail is not deployed.
- **AC14.** A page that does not exist returns 404 on the live site, and a server error does not show Django's debug page.

## One-time steps for the owner

1. Sign in to render.com with GitHub and let Render read `hungle-agilityio/ai-training` only.
2. New, Blueprint, pick the repository; Render reads `render.yaml`. Accept the generated `DJANGO_SECRET_KEY`.
3. If `reviewradar.onrender.com` is taken, set `DJANGO_ALLOWED_HOSTS` to the address Render shows and tell the Project, so the README address is fixed.

## Edge cases

- Empty: on a fresh start the demo data is always there; a branch without reviews shows no score, as today.
- Asleep: the first visit after 15 idle minutes waits about a minute; data is the fresh demo data again.
- Failed deploy: Render keeps the previous version online; the owner sees the failure in Render's deploy list.
- Permissions: anyone with the link can read the demo pages; nothing can be written from the web.

## Decisions

| Question | Chosen | Rejected | Why |
|---|---|---|---|
| Q1 Host | Render free | PythonAnywhere free; Koyeb free | Deploys from GitHub by itself, HTTPS, no card. PythonAnywhere cannot redeploy on merge reliably; Koyeb needs a card. |
| Q2 Database and data | SQLite, `migrate` + `seed_demo_data` on each start | Render free Postgres; Neon Postgres | The web never writes data; no database to manage or renew. Render Postgres expires after 30 days. |
| Q3 Deploy trigger | Render auto-deploy after CI checks pass | GitHub Actions deploy job; deploy without waiting for CI | Fewest parts, no `.github/` change, red CI never goes live. |
| Q4 Who can see it | Public, `noindex` | Basic auth password; public and indexed | Demo data only and no write pages; one meta line keeps it off search engines. |
| Q5 Domain | Render subdomain `*.onrender.com` | Free outside domain (is-a.dev, eu.org) | Ready at once with HTTPS; a custom domain can come later. |

## Design

Nothing visible to users changes in the pages; no design card.
