# Decisions during build: T1 (#526)

| Question | Chosen | Rejected | Why | From |
|---|---|---|---|---|
| Which parts the hook gives `guarded_kind` | Absolute parts for rule and gate, `in_plugin_source` kept for the plugin kind between them | Git-root parts for everything | Every refusal of main stays identical: a `.claude` folder above the git root is still refused, a path outside a repository gets no plugin refusal | build |
| How the hook binds the names | The loaded module object, attribute access | Re-assigning the names in the hook | AC2 "defines none of them itself"; the hook runs with `python3 -I` so a plain import cannot work | build |
| Message of a failed load in the hook | `<file> not checked: guarded_paths.py could not be loaded (<error>)`, after the FLOW_ALLOWED_EDITS allow so a listed guarded_paths.py can still be repaired | Refuse listed files too | The owner decided refusal; the place and wording were open | build |
| When ops loads the module | Lazily, cached per module path, config read at call time | At import | One load per tick; a config or module error fails closed instead of breaking the import | build |
| marketplace.json | Unchanged | Add a version to it | It carries no version, so `plugin.json` is the only one to raise; not in the issue's files | build |
| A `guarded_kind` that raises | Fails closed on both sides: the hook refuses the edit (`<file> not checked: guarded_paths.py could not answer (<error>)`), `ops/epic_pull_request.py` lists the file | Let the error through | An uncaught error ends the hook with exit code 1, which does not block the edit; found by the code review | build |
| The lists of guarded names in the work-queue skill text and the hooks README | Unchanged, they do not name `flow.toml` yet | Update them in this build | Not in the issue's files; raised in the pull request for the owner | build |
| Empty path in `guarded` when the module is missing | Stays False | True | A diff line always has a path; as on main | build |
