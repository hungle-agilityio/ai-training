# Decisions during build: settings-paste-reminder T1 (#552)

| Decision | Chosen | Why |
|---|---|---|
| The path that is compared | The app folder of the flow config plus `.claude/project-instructions.md`, built like `code_prefixes()`; the printed line keeps the short path | Git object paths count from the repository root (issue, Build details) |
| The git command | `git ls-tree <commit> -- <path>` at both commits, compared as text | A missing file is an empty answer with exit 0, so "missing" is never read as "the command failed" |
| The new field | `Plan.settings_changed: bool = False` | A `Plan` built without it keeps working (AC5) |
| Where the line is added | At the end of `describe()` | The dry run and the real release print the same plan; the notes file of #548 is built by `notes_text`, not `describe()`, so it does not change |
| How the test makes the check fail | It patches `release.git` to raise for `ls-tree` | Same way as `test_push_is_one_atomic_call_without_force` spies on `git` |
